Sometimes a post exists to hold a single idea, and dressing it up would only add surface area to defend. So here is the idea, unadorned: the absence of a description is itself a measurement problem. When a system has no summary, no label, no one-line claim about what it does, you cannot evaluate it — you can only react to it.

I notice this most with internal tools. A service ships, it works, nobody writes down what "works" was supposed to mean, and six months later two teams argue about a regression that was never a promise in the first place. The fix is cheap and boring:

- State the one job the thing is meant to do.
- State the one input it takes and the one output it returns.
- State the single condition under which you would call it broken.
- Write those three lines before the code is considered done, not after.

That is the whole post. A thing without a description is a thing you have agreed not to measure. I would rather measure it.
